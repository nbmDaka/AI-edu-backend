# AI-шлюз платформы

Это наш отдельный AI-сервис, перенесённый из локального проекта без демонстрационной страницы, материалов старой лекции, 3D-ресурсов, секретов и баз. Экспортированы используемые маршруты `/api/chat`, `/api/tts`, `/api/transcribe` и `/api/health`.

Нужны Node.js 24, отдельная PostgreSQL-база тьютора, ключ OpenAI и случайный `API_SHARED_KEY`. Установите `npm ci`. Для сборки достаточно `OPENAI_API_KEY=build-only-placeholder npm run build`: реальный ключ не требуется и не должен попадать в сборочную конфигурацию. Перед запуском загрузите настоящее окружение из `.env.example` с заменёнными заглушками; поддерживается стандартный `.env.local` Next.js. Не публикуйте этот файл.

```bash
npm ci
OPENAI_API_KEY=build-only-placeholder npm run build
# Загрузите настоящее окружение, в том числе DATABASE_URL.
npx prisma db push
npx next start -H 127.0.0.1 -p 3001
```

Prisma db push выполняйте только для отдельной базы тьютора после резервной копии. SQLite доступна на Node 24 для локальной проверки, но не используйте локальный файл для нескольких экземпляров сервиса.

Для озвучки отдельно запускается `local-tts/app.py`. Установите requirements в Python-окружение и задайте пути к Linux-исполняемому файлу Piper и русской модели `.onnx` с `.onnx.json`. Модель и Piper в репозиторий не включены. Запуск: `python -m uvicorn app:app --host 127.0.0.1 --port 8002` из `local-tts`, с тем же серверным окружением. `LOCAL_TTS_URL` шлюза должен указывать на этот процесс.

Если локальный `LOCAL_STT_URL` недоступен, распознавание использует OpenAI transcription. На фронтенде записывается отдельный вопрос, распознанный текст можно отредактировать перед отправкой. Это не непрерывный realtime-разговор. Озвучка пока только русская, без 3D-аватара.

Порты шлюза и Piper должны оставаться во внутренней сети. Браузер обращается только к авторизованному Django. В Django задайте `AI_SERVICE_URL` и `AI_SERVICE_API_KEY`, совпадающий с `API_SHARED_KEY` шлюза. Для процессов настройте supervisor и рестарт. Для Docker используйте имена сервисов вместо localhost; Dockerfile здесь собирает только шлюз, не Python/Piper и не PostgreSQL.

Существующий CI/CD backend автоматически публикует Django, но не запускает этот отдельный сервис. Перед объединением PR программисту нужно однократно развернуть шлюз, Piper и серверные переменные. Сначала backend, затем frontend. Не считайте обновление интерфейса подтверждением готовности AI.

В локальной проверке получены ответы по двум разным лекциям, непустое WAV-аудио и распознанная запись. Первый длинный запрос озвучки завершился по таймауту; последующие работали. Холодный старт, очередь синтеза, длительные ответы и нагрузку нужно проверить на целевом сервере. Версии исходного AI-шлюза сохранены; перед публичным открытием его API нужна отдельная проверка зависимостей и безопасности.
