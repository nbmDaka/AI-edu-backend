# Виртуальная мастерская генерации лекции — backend

Зарегистрирован `lecture_workshop@1.0.0`. Создайте учебный элемент `PRACTICE` через существующее API,
сохраните и опубликуйте его конфигурацию через `items/{short_id}/practice/draft/`:

```json
{
  "practice_type": "lecture_workshop",
  "plugin_version": "1.0.0",
  "title": "Виртуальная мастерская генерации лекции",
  "description": "Напишите запрос в чате и подготовьте учебную лекцию.",
  "config": {
    "instructions": ["{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Подготовьте лекцию для своей аудитории.\"}]}]}"],
    "criteria": [{"title": "Лекция соответствует заданию", "description": "", "is_required": true}]
  }
}
```

Публикация и настройка задания доступны только администратору. Workspace использует существующие
попытки и закреплённую версию задания. Все его API требуют сессионную авторизацию, CSRF для записи,
владение документом и доступ к опубликованному учебному элементу, включая блокировки модулей.
Frontend сначала показывает общее задание с инструкцией и критериями, затем выбранный инструмент,
после выполнения — самопроверку с окончательной сдачей. Администратор выбирает `lecture_workshop`
или `guided_assignment`, сохраняя общие поля при переключении. Старые версии `checklist_practice`
и мастерской остаются доступны, их опубликованные данные и история сохраняются.
Инструкция, название, описание и критерии закреплённой версии передаются AI как контекст задания.

## AI API и локальный worker

В **локальном** окружении задайте переменные backend (ключ не передаётся frontend):

```dotenv
AI_BASE_URL=https://your-provider.example/v1
AI_API_KEY=your-local-provider-key
AI_MODEL=your-provider-model
AI_TIMEOUT_SECONDS=120
```

Поддерживается HTTP API, совместимый с Chat Completions: `POST {AI_BASE_URL}/chat/completions`,
`messages`, `model`, `response_format={"type":"json_object"}`. Выберите модель с поддержкой JSON output.
Имя модели не зашито в код. Пустые `AI_BASE_URL` или `AI_MODEL` отключают запуск операций (`503`).
Для локального провайдера без авторизации `AI_API_KEY` можно оставить пустым. Перенаправления HTTP
запрещены, чтобы не передавать ключ другому адресу. Таймаут допускает 1–600 секунд и ограничивает
весь дочерний процесс AI-вызова, включая соединение, чтение и разбор ответа. Дополнительных зависимостей нет.

Миграция `activities/0004_workspace_models.py` добавляет три таблицы. Применять её следует только
к подготовленной **изолированной локальной БД**. Следующие команды — инструкции для локального
окружения; не выполняйте их против production или общей рабочей базы:

```bash
python manage.py migrate
python manage.py run_workspace_worker
```

Для непрерывного worker необходим PostgreSQL (`DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`,
`DATABASE_USER`, `DATABASE_PASSWORD`). Backend и worker должны использовать одну локальную БД и AI-конфигурацию.
В Docker Compose отдельный сервис `workspace-worker` запускает обработку очереди автоматически.
Он использует тот же `.env` и PostgreSQL, что и backend. Для запуска в настроенном локальном
окружении используйте `docker compose up -d --build workspace-worker`.
После изменения `.env` пересоздайте backend и workspace-worker, чтобы оба получили новые переменные.

`--poll-interval 2` задаёт частоту опроса очереди; `--once` восстанавливает истёкшие аренды,
обрабатывает не более одной операции и завершает процесс. `--once` также доступен для локальных
проверок на SQLite; конкурентная обработка поддерживается только на PostgreSQL.
Worker ничего не мигрирует. В production он использует тот же образ и тег, что и backend;
CI/CD обновляет и запускает оба сервиса после миграций. Политика `restart: unless-stopped`
перезапускает worker после сбоя. `import-worker` обрабатывает импорт файлов и не заменяет workspace-worker.

PostgreSQL worker получает задачу через `SELECT FOR UPDATE SKIP LOCKED`, назначает уникальный
токен аренды и освобождает транзакцию перед HTTP-вызовом. Аренда длится таймаут операции + 30 секунд.
После аварийного завершения worker истёкшие операции возвращаются в очередь, максимум три получения;
после третьего сбоя — `FAILED / operation_timeout`. Возвращённый старым worker результат не применяется.
При каждой обработке проверяются доступ, состояние попытки и ревизия документа.

## API workspace

### Диалог и Word-файлы

Новый клиент отправляет `kind: "chat"`. AI сначала возвращает ограниченный план действия:
`clarify`, `generate`, `edit`, `export` или `unsupported`. Сервер валидирует план и разрешает
только полную лекцию, её редактирование и DOCX. Режима «только план», PPTX, PDF и других
выходных форматов нет. Уточняются тема, аудитория, длительность и язык; обычно 1–2 хода,
максимум 3 последовательных уточнения, затем используются разумные значения по умолчанию.
История и требования сохраняются на сервере и восстанавливаются после перезагрузки.

У ответа ассистента появились `choices` (варианты ответа в текущем сообщении) и `artifact`
(вложение с `name`, `size`, `revision`, `url`). Файл создаётся из сохранённой версии лекции,
а не из исполняемого кода модели. DOCX содержит заголовки, списки, нумерацию и номера страниц.
Небольшой неизменяемый снимок хранится в БД (до 512 КБ). Повторное скачивание не обращается
к AI и не расходует квоту; доступ проверяется при каждом скачивании, включая завершённые работы.

Лимиты применяются на сервере ко всем диалогам пользователя за скользящий час:

| Действие | Лимит |
| --- | --- |
| Активные запросы (`PENDING` + `RUNNING`) | 10 на пользователя; один на документ |
| Полная генерация | 5 в час |
| Редактирование | 10 в час |
| Создание DOCX | 10 в час; повторное скачивание бесплатно |
| Объём лекции | 3000 слов, включая заголовки |
| Сообщение пользователя | 8000 символов |

Резервирование квот сериализовано блокировкой пользователя и идемпотентно для операции.
Неуспешные AI-вызовы также учитываются; уточнения не расходуют квоты генерации/редактирования.
Для генерации сразу в Word резервируются и генерация, и DOCX до вызова генератора.
Превышение квоты в обработчике даёт `FAILED / workspace_limit`, превышение активных запросов — HTTP 429.
Старые `generate`/`improve_prompt` также учитывают квоты и сохраняют совместимость API.

Worker запускает до 10 параллельных операций (`--concurrency 1..10`, по умолчанию 10).
Общая аренда и таймаут распространяются на классификацию запроса и генерацию вместе.
Максимум ответа AI: 2048 токенов для плана действия и 16000 для полной лекции;
в статистику успешной операции суммируются оба вызова.
Для обновления необходима миграция `activities/0007_lecture_chat_and_artifacts.py`
и пересоздание backend и workspace-worker из нового образа с `python-docx`.

### Endpoints

Все пути относительны `/api/v1/`:

| Метод и путь | Назначение |
| --- | --- |
| `POST items/{short_id}/practice/workspace/` | Создать документ и начать попытку существующим механизмом; вернуть имеющийся документ активной попытки |
| `GET workspace/documents/{id}/` | Загрузить свой документ |
| `PATCH workspace/documents/{id}/` | Изменить `parameters` и/или `content`, обязательно передав `revision` |
| `GET workspace/documents/{id}/messages/` | История сообщений с обычной пагинацией |
| `POST workspace/documents/{id}/operations/` | Запустить `generate` или `improve_prompt`; ответ `202` с ID операции |
| `GET workspace/operations/{id}/` | Состояние, результат и метрики операции |
| `GET workspace/artifacts/{id}/download/` | Приватное скачивание готового DOCX без новой генерации |

Для чата достаточно `{"language": "ru"}` (`ru`, `kk`, `en`; по умолчанию `ru`).
Тема, название и остальные пожелания задаются в сообщении. Сервер подставляет служебные значения
параметров; AI получает инструкцию отдавать приоритет запросу пользователя. Существующий формат
с полным объектом `parameters` также поддерживается:

```json
{
  "parameters": {
    "discipline": "Педагогика",
    "topic": "Методы активного обучения",
    "course": "2 курс бакалавриата",
    "audience": "Будущие преподаватели",
    "duration_minutes": 45,
    "difficulty": "intermediate",
    "learning_outcomes": ["Объяснять методы активного обучения", "Подбирать методы под учебную цель"],
    "language": "ru"
  }
}
```

`course` — описание курса/года обучения, не ID курса платформы. Продолжительность: 5–480 минут;
сложность: `beginner/intermediate/advanced`; язык: `ru/kk/en` (для казахского используется ISO-код `kk`).
При первом создании возвращается `201`, при повторном — `200` без перезаписи введённых параметров.
Один документ соответствует одной попытке. Сданный документ доступен для чтения; новая попытка
создаёт отдельный документ, сохраняя предыдущий.

Тело запуска операции (используйте новый UUID для каждого нового запроса):

```json
{
  "request_id": "842d57ac-4b52-45b4-b165-5233a149989c",
  "revision": 1,
  "kind": "generate",
  "prompt": "Добавь примеры из практики преподавателя и вопросы для обсуждения."
}
```

Повтор того же `request_id` с тем же запросом возвращает ту же операцию и не дублирует сообщения.
Изменение запроса при прежнем UUID, устаревшая ревизия или вторая активная операция дают `409`.
`improve_prompt` возвращает `result.improved_prompt` и сообщение ассистента; **не генерирует лекцию**,
не изменяет параметры, содержание или ревизию. Запрос улучшения не запускает автоматически `generate`.
История чата и текущая лекция используются как многоходовый AI-контекст.
`target_section_id` и операции изменения отдельных разделов пока не принимаются.

`generate` валидирует результат, сохраняет лекцию и увеличивает ревизию на 1. Его результат:
`{"content": <лекция>, "revision": <новая ревизия>}`. Если во время AI-вызова документ сохранён вручную,
операция завершается `FAILED / revision_conflict`, сохраняя новую ручную редакцию. Результат применяется
атомарно один раз. Основные коды ошибок: `ai_timeout`, `ai_http_error`, `ai_rate_limited`,
`ai_invalid_response`, `ai_invalid_content`, `revision_conflict`, `access_revoked`, `submission_closed`.
Ошибки содержат только безопасные коды, без ключей, заголовков или тела ошибок провайдера.

Для диагностики AI-ошибок worker пишет в логи ID операции и внутренний код ошибки.
Для HTTP-ошибок добавляются `http_status`, `provider_code`, `provider_type`, `provider_param`
и `request_id` (из `x-request-id`), если провайдер их вернул. Например:
`Workspace operation 5: ai_http_error diagnostics={"http_status": 400, "provider_code": "unsupported_parameter", "provider_param": "response_format", "request_id": "req_example"}`.
Допускаются только ограниченные по длине идентификаторы; значения с ключом API отбрасываются.
Текст `message`, тело ответа, запрос пользователя и заголовок Authorization не логируются.
Диагностика доступна через `docker compose logs --tail 100 workspace-worker`;
в API операции по-прежнему возвращается только внутренний `error_code`.

В операции сохраняются фактическая модель (или запрошенная, если провайдер не вернул имя), длительность
последнего выполнения в миллисекундах и `attempts`. `input_tokens/output_tokens/total_tokens` берутся
из `usage.prompt_tokens/completion_tokens/total_tokens`. Стоимость берётся из `usage.cost` или `cost`,
валюта — `usage.cost_currency` или `cost_currency`; при отсутствии данных стоимость и токены `null`.
По тарифам модели стоимость не оценивается. Аварийный повтор может повторно вызвать платный API:
гарантия однократности относится к применению результата в БД, а не к биллингу внешнего провайдера.

## Структура лекции и ручное редактирование

`content` — объект `{"title": "Название", "sections": [...]}`. Версия схемы — 1.
Каждый раздел имеет `id`, `title`, `content`. Строго заданные ID и порядок:

1. `goal` — цель;
2. `learning_outcomes` — результаты обучения;
3. `outline` — план;
4. `introduction` — введение;
5. `main_material` — основной материал;
6. `examples` — примеры;
7. `key_concepts` — ключевые понятия;
8. `conclusions` — выводы;
9. `control_questions` — контрольные вопросы;
10. `self_study` — самостоятельные задания.

Например, один раздел (в полном документе должны присутствовать все десять):

```json
{
  "id": "goal",
  "title": "Цель лекции",
  "content": {
    "type": "doc",
    "content": [{"type": "paragraph", "content": [{"type": "text", "text": "Научиться выбирать методы активного обучения."}]}]
  }
}
```

Содержание раздела — объект Tiptap, совместимый с существующим `LessonTextEditor` через
`JSON.stringify(section.content)`. Поддерживаются paragraph, heading уровней 2/3, списки,
blockquote, codeBlock, text, hardBreak и форматирование bold/italic/code/link.
Ссылки допускают только HTTP, HTTPS и mailto. HTML, изображения и неизвестные узлы/поля отклоняются;
есть лимиты размера (250 KB), вложенности и количества узлов. ID разделов сохраняются при генерации
и редактировании. Пустое `{}` допускается только как исходное содержание ещё не созданной лекции;
сохранить его через PATCH нельзя. Завершение практики не требует сгенерированной лекции.

Для сохранения передайте `PATCH` с текущей `revision` и полной структурой `content` и/или полным
объектом `parameters`. Сервер увеличит ревизию и вернёт обновлённый документ. Сохранение не завершает
практику и не меняет прогресс. Для сдачи используйте существующий `POST items/{short_id}/practice/`:

```json
{
  "submission_id": 123,
  "submission_data": {"completed": true, "checks": [true], "document_id": 456, "document_revision": 2}
}
```

Для новых заданий с `instructions` обязательны полная лекция и самопроверка: все обязательные критерии
должны быть подтверждены. Сервер проверяет принадлежность документа, актуальность ревизии и отсутствие
незавершённых операций, добавляет снимок документа. Оценка сохраняется с источником `SELF_ASSESSMENT`,
прогресс — 100%. Повторная отправка не создаёт второй результат. Можно отправить `{completed, checks}`,
тогда сервер сам найдёт документ попытки. У исторических версий без инструкции сохранён прежний контракт
`{completed: true}` с источником `COMPLETION`; он не применяется к новым заданиям.
В `guided_assignment` передаются `{report, artifact_url, checks}`; неподтверждённые обязательные критерии
возвращают 400 и оставляют попытку открытой. Новая миграция БД для общего сценария не требуется.

`GET items/{short_id}/practice/` возвращает `submission.document_id`, поэтому чат восстанавливается
без localStorage. Сообщения ассистента содержат `content` с полной лекцией из результата своей операции;
пользовательские сообщения имеют `content: null`. Каждый новый запрос использует последние 12 сообщений
успешных операций и текущую лекцию, позволяя уточнять материал в диалоге.
Для следующего типа виртуальной работы потребуется новый PracticePlugin со схемой и методами
`workspace_type`, `workspace_schema_version`, `validate_workspace_parameters`,
`validate_workspace_content`, `workspace_prompt`; общие модели и API не меняются.

## Безопасные локальные проверки

Тесты используют mock AI API; реальные обращения и списания не выполняются. В PowerShell можно
принудительно выбрать тестовую SQLite в памяти, не используя рабочую PostgreSQL/MinIO/Redis:

```powershell
$env:DEBUG='true'
$env:SECRET_KEY='local-workspace-test-secret'
$env:DATABASE_HOST=''
$env:REDIS_URL=''
$env:S3_ENDPOINT_URL=''
python -c "import os; os.environ['DJANGO_SETTINGS_MODULE']='config.settings'; import django; from django.conf import settings; settings.DATABASES['default']['NAME']=':memory:'; django.setup(); from django.core.management import call_command; call_command('test', 'apps.activities.test_workspace', 'apps.activities.tests')"
```

Для полной регрессии уберите названия модулей из `call_command('test', ...)`.
Тест `WorkspacePostgreSQLTests` выполняется только при подключении к **изолированной тестовой**
PostgreSQL: он проверяет `SKIP LOCKED` через независимое соединение. На SQLite этот тест пропускается.
Не указывайте реквизиты production при запуске тестов. Проверки схемы и миграций:
`python manage.py check`, `python manage.py makemigrations --check --dry-run`,
`python manage.py spectacular --validate` (также в изолированном локальном окружении).
