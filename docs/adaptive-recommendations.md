# Адресные рекомендации после попытки

Развёртывание: сначала выполнить `python manage.py migrate` на backend (миграция education `0020_learningitem_competency_keys`), затем обновить frontend. Поле JSON `LearningItem.competency_keys` по умолчанию пустое; существующие материалы и попытки не изменяются. Обратная миграция удаляет связи, но не снимки рекомендаций в попытках.

В существующей админке откройте редактор лекции или практики. В блоке «Компетенции для рекомендаций» введите ключи из поля компетенции вопросов итогового теста, по одному на строку, и сохраните связи отдельно от учебного содержимого. Для ключей применяется тот же `strip().casefold()`, что в оценивании. API принимает `competency_keys: string[]` через POST/PATCH `/api/v1/items/` и `/api/v1/items/{short_id}/`: максимум 50 ключей, каждый непустой до 100 символов; дубли удаляются. Привязки к тестам запрещены. Редактирование доступно только администратору. Настраивать связи можно заранее в черновике; подбор использует только опубликованные и доступные лекции/практики текущего модуля.

Правило версии 1 находится в `apps/education/recommendations.py`: показатель компетенции после штатного обновления профиля строго ниже `RECOMMENDATION_REFERENCE = 0.50`. Это отдельный продуктовый ориентир рекомендаций, а не научно установленный минимум компетенции, вероятность освоения или порог допуска. Статья (§3–4, рисунки 1–2) разделяет формальное оценивание и поддержку обучения; её сравнение экспериментальных политик не требует менять действующую формулу. Сохраняются веса 0.40/0.25/−0.15/0.20, обновление компетенций 0.40/0.60, модульный порог и обязательное общее повторение после неуспеха. `passed`, `module_passed`, накопленное `module_completed` по-прежнему различаются.

Компетенции упорядочены по возрастанию показателя, затем по нормализованному ключу. Все подходящие материалы внутри группы идут по `position`, затем `id`. Один материал может относиться к нескольким компетенциям. Отдельного ML, ранжирования по популярности, нового справочника или дополнительных блокировок нет. Смена константы действует только на новые попытки; при изменении смысла правила следует повысить версию.

`TestAttempt.adaptive_result.recommendations` хранит неизменяемый снимок: `version`, `reference_score`, `groups[]` с `competency`, `score`, `reason: below_reference`, `materials[]` с исходными `item_id`, `short_id`, `module_id`, `title`, `type`; `fallback` равен `no_data`, `no_weak_competencies`, `unmapped_competencies` или null. Сохраняются и пустые группы, чтобы было понятно отсутствие связей. При частичном покрытии показываются доступные рекомендации и общий план повторения. Это снимок назначения материала, а не резервная копия его полного содержимого.

Все ответы попыток (POST и история, в том числе `/api/v1/attempts/`) добавляют в каждый материал `available_item_short_id: string | null`, проверяя текущее существование, исходный модуль/тип, публикацию материала, лекции/версии практики и стандартный доступ пользователя/блокировки. Это вычисляемое поле не записывается в снимок. UI строит ссылку только из него, исходный `short_id` не является разрешением доступа. При изменении названия или связей старое назначение остаётся объяснимым; при удалении, закрытии или отзыве доступа ссылка отсутствует. Конечный API материала повторно проверяет доступ при переходе. Старые попытки без `recommendations` не пересчитываются и честно предлагают общее повторение.

Точки расширения: `recommend_materials` вызывается в существующей транзакции оценки перед сохранением попытки; `resolve_recommendations` только разрешает актуальные ссылки при сериализации. Общий журнал учебных событий и новый AI-контекст здесь не реализованы.

Проверки: `apps.education.test_recommendations` вместе с `apps.education.test_adaptive`; frontend `src/Recommendations.test.tsx`, общий Vitest/build; реальная локальная интеграция `e2e/adaptive.integration.e2e.ts` с `e2e/fixtures/adaptive_backend.py`. Интеграционная фикстура создаёт отдельную временную SQLite и не загружает backend .env. Запускать из backend с PYTHONPATH на backend; frontend `API_PROXY_TARGET=http://127.0.0.1:8017`, JSON из строки `AI_EDU_INTEGRATION_FIXTURE` передать одноимённой переменной Playwright. Это не проверка PostgreSQL или production.
