# Аналитика обучения

`GET /api/v1/admin/analytics/` — агрегированная статистика только для активного
администратора (`IsPlatformAdmin`). Endpoint доступен только для чтения и не
возвращает имена, email, ответы тестов или идентификаторы студентов.

| Параметр | Значения | По умолчанию |
| --- | --- | --- |
| `period` | `7d`, `30d`, `90d`, `all` | `30d` |
| `track` | Положительный ID траектории | Все траектории |
| `course` | Положительный ID курса | Все курсы |

Несуществующий или недоступный ID, неверный период и курс из другой выбранной
траектории возвращают `400`. Ответ содержит `generated_at`, `since`, применённые
фильтры, варианты фильтров, сводку и строки траекторий, курсов и модулей.
Контракт описан в OpenAPI. HTTP-кэширование отключено (`private, no-store`).

## Определения

- Популяция: неудалённые пользователи с ролью `STUDENT`, включая неактивные
  аккаунты. Администраторы исключены. `total_students` — число студентов на всей
  платформе, независимо от фильтров.
- Контент: неудалённые опубликованные курсы активных опубликованных траекторий,
  их опубликованные модули и элементы. Фильтры выбирают контент, а не текущую
  траекторию пользователя: история студента остаётся в показателях курса после
  смены его траектории или доступа.
- `assigned_students`: текущее число студентов, назначенных на траекторию.
  Назначение не считается началом обучения и не ограничивается выбранным курсом.
- `started_students`: уникальные студенты с записью прогресса, попыткой теста
  (успешной или нет) либо практической работой, за всё время.
- `active_students`: уникальные студенты с учебной активностью за последние
  N суток до `generated_at`, включая границы периода. Используются `updated_at`
  прогресса/практики и `completed_at` попытки теста. Будущие даты исключаются.
  При `all` учитывается вся сохранённая активность.
- `completed_students`: уникальные студенты, завершившие все текущие
  опубликованные элементы курса или модуля, согласно `is_completed` прогресса.
  Это определение совпадает с `learning_summaries`; пустой курс или модуль не
  считается завершённым. Сводка считает студентов, завершивших хотя бы один
  выбранный курс. Период не ограничивает накопленное завершение.
- `completion_rate`: `completed_students / started_students * 100`, округление
  до одного десятичного знака; без начавших — `0`.

Студент учитывается один раз в каждой сущности. Суммы строк курсов могут превышать
число уникальных студентов. Диаграмма завершения использует пары «студент–курс»,
поэтому её количество завершений может превышать число завершивших студентов
на карточке.

Данные описывают текущую программу: публикация или удаление могут изменить
накопленные показатели. Источник не хранит полную историю событий, поэтому
дневные посещения, длительность сессий и исторические сравнения не рассчитываются.
Для них потребуется отдельный журнал учебных событий.

## Реализация и проверка

Источники группируются в SQL до объединения уникальных пар «студент–модуль».
Количество запросов не растёт с количеством студентов или курсов; тест проверяет
отсутствие N+1. Память зависит от количества таких пар, а не количества попыток
и содержимого ответов. Для значительно больших объёмов можно перенести агрегаты
в периодически обновляемую витрину.

Frontend: `/admin/analytics`, фильтры в URL, кэш результата на 60 секунд,
ручное обновление. В таблицах поиск, сортировка, страницы по 10 строк и ссылки
в конструктор. CSV содержит все строки выбранной таблицы после поиска, а не
только страницу, и метаданные фильтров. Кавычки и формулы таблиц экранируются.

Нужно обновить backend и frontend. Новые миграции и переменные окружения не нужны.

```bash
python manage.py test apps.education.test_analytics --settings=config.settings_test --noinput
```

Во frontend:

```bash
npm test -- src/admin/AnalyticsPage.test.tsx src/admin/AdminWorkspace.test.tsx
npx playwright test e2e/analytics.e2e.ts
npm run build
```

Браузерные тесты используют фикстуры: desktop/mobile, фильтры, модули, CSV.
Численные расчёты отдельно проверяются на тестовой базе Django.
