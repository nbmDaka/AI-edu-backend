# Письма аккаунта через Resend

Новые пользователи подтверждают email перед входом. Регистрация создаёт аккаунт и
отправляет письмо, но не создаёт сессию. Существующие аккаунты и аккаунты, созданные
администратором, сохраняют доступ без нового подтверждения. Миграция
`accounts.0006_user_email_verification` добавляет признак необходимости подтверждения
только для новых публичных регистраций.

## Настройка

1. Добавьте и подтвердите домен `aiedu.com.kz` в [Resend](https://resend.com/docs/dashboard/domains/introduction).
   Внесите DNS-записи, которые покажет Resend для этого домена. Не заменяйте действующие
   MX-записи основной почты записями для входящих писем Resend: для отправки получение
   писем через Resend не требуется.
2. Создайте API-ключ с правом отправки для этого домена.
3. Укажите в `.env` бэкенда, включая `.env` на production-сервере:

```dotenv
RESEND_API_KEY=re_your_server_side_key
DEFAULT_FROM_EMAIL=AI Edu <noreply@aiedu.com.kz>
PUBLIC_SITE_URL=https://aiedu.com.kz
EMAIL_BACKEND=common.email.ResendEmailBackend
EMAIL_TIMEOUT=10
EMAIL_VERIFICATION_TIMEOUT=86400
PASSWORD_RESET_TIMEOUT=3600
```

Ключ хранится только в окружении бэкенда. Не добавляйте его в `VITE_*`, исходники,
шаблоны писем или репозиторий. Docker Compose уже читает `.env` для backend.
Обычный production-deploy применяет миграции автоматически. При ручном обновлении:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml run --rm backend python manage.py migrate --noinput
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --no-deps --force-recreate backend
```

Для локальных ссылок задайте `PUBLIC_SITE_URL=http://localhost:5173` с фактическим
портом frontend. Для локального просмотра без отправки можно временно использовать
`EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend`; production использует Resend.

## Сценарии

- `POST /api/v1/auth/register/` — создаёт пользователя и отправляет подтверждение.
  Ответ `201` содержит `verification_required: true`; автоматического входа нет.
- `POST /api/v1/auth/verify-email/` с `token` — подтверждает адрес. Ссылка подписана,
  привязана к адресу и аккаунту, действует 24 часа. Повторное подтверждение той же
  ссылки безопасно. Для подтверждения на странице требуется нажатие кнопки:
  автоматический просмотр ссылки почтовым сканером не активирует аккаунт.
- `POST /api/v1/auth/verify-email/resend/` с `email` — повторная отправка. Доступна
  из экрана регистрации и из формы входа для неподтверждённого аккаунта.
- `POST /api/v1/auth/password-reset/` с `email` — отправляет ссылку сброса пароля.
- `POST /api/v1/auth/password-reset/confirm/` с `uid`, `token`, `new_password` —
  задаёт новый пароль. Ссылка действует 60 минут, перестаёт работать после смены
  пароля; прежние сессии также теряют доступ. Сброс не подтверждает email автоматически.

Сроки ссылок настраиваются переменными окружения. Ответы на запросы повторного
подтверждения и сброса одинаковы для неизвестных, заблокированных и удалённых аккаунтов.
Отправка ограничена отдельно по IP и адресу: 20 запросов с IP и 3 на адрес за 5 минут
для каждого сценария. Все изменяющие запросы требуют CSRF.

Письма содержат HTML и текстовую версию; адрес отправителя по умолчанию —
`AI Edu <noreply@aiedu.com.kz>`. Ссылки строятся из `PUBLIC_SITE_URL`, а не из заголовка
запроса, и используют hash-маршруты frontend, чтобы токен не попадал в HTTP-путь.

Доставка синхронная, с таймаутом 10 секунд. Если Resend недоступен или ключ не настроен,
аккаунт остаётся ожидающим подтверждения, и пользователь может запросить новое письмо.
Автоматической фоновой повторной отправки нет. Ошибка записывается в журнал
`apps.accounts.emails` с ID пользователя и классом ошибки; пароли, токены и API-ключ
в журнал не попадают. Факт доставки проверяется в Resend Emails/Logs.

## Проверки

```bash
python manage.py test apps.accounts --settings=config.settings_test --noinput
```

Тесты используют локальный почтовый outbox и замоканный HTTPS-транспорт, реальные письма
не отправляются. Для проверки реальной доставки после настройки зарегистрируйте
тестовый аккаунт с доступным вам почтовым ящиком и пройдите оба сценария.
