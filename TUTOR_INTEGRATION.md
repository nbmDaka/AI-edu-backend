# Подключение нашего тьютора

Браузер отправляет вопрос на `POST /api/v1/tutor/chat/` с сессионной cookie и CSRF-токеном Django. Django проверяет доступ к текущей лекции, читает опубликованные блоки из базы и передаёт их нашему существующему AI-шлюзу. Поток SSE возвращается в браузер без накопления всего ответа.

## Настройка сервера

Укажите в окружении backend:

```dotenv
AI_SERVICE_URL=http://ai-tutor:3001
AI_SERVICE_API_KEY=<значение API_SHARED_KEY из окружения нашего AI-шлюза>
AI_SERVICE_TIMEOUT=90
AI_TUTOR_RATE=20/min
```

AI-шлюз находится в `services/ai-tutor`; это отдельный процесс, перенесённый из нашего локального приложения `E:\eduai\AI`. Разверните его в доступной для Django внутренней сети. Он требует собственных настроек OpenAI, базы данных и квот. Стандартный Docker Compose этого репозитория сам его не запускает. В production backend требует непустой сервисный ключ. Не помещайте этот ключ и ключ OpenAI в переменные `VITE_*` или исходники frontend.

Фронтенд должен обращаться к API через тот же домен. Внешний reverse proxy направляет `/api/v1/` в Django, а остальные адреса - во frontend. Для SSE отключите буферизацию и задайте таймаут чтения не меньше 120 секунд:

```nginx
location /api/v1/tutor/ {
    proxy_pass http://backend:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 120s;
}
```

Параметры запроса: `context_type` (`lesson` или `item`), `context_id` (short_id), `session_id` (UUID), `messages` (до 12 сообщений с ролями `user` / `assistant`). Последнее сообщение должно быть вопросом пользователя. Текст лекции и ID курса берутся только с сервера. Сессия AI содержит ID пользователя и лекции, чтобы одинаковые клиентские UUID не объединяли диалоги разных студентов.

Тьютор доступен для лекций, включая старые ссылки `/lessons/`. На страницах тестов ответы теста ему не передаются. Tiptap JSON, Markdown, код и текст таблиц преобразуются в контекст; для изображений передаются только подписи и alt-текст. Распознавание содержимого изображений в эту интеграцию не входит.

## Голос

`POST /api/v1/tutor/speech/` принимает `context_type`, `context_id`, `text` и `language=ru`; возвращает WAV. `POST /api/v1/tutor/transcribe/` принимает те же параметры контекста, multipart-поле `file` до 10 МБ и `language=ru|kk|en|auto`; возвращает распознанный текст. Оба маршрута проверяют доступ к лекции, CSRF и общую квоту тьютора. Ключи остаются на сервере.

Наш AI-шлюз использует `LOCAL_TTS_URL` для Piper и `LOCAL_STT_URL` для локального распознавания. Если STT недоступен, существующий шлюз может использовать OpenAI transcription. Разверните сервис озвучки вместе со шлюзом; одного Django недостаточно. В Linux задайте действительные `PIPER_EXE` и `PIPER_MODEL_RU`, поскольку Windows-пути по умолчанию там не работают. Озвучка сейчас только на русском. Для доступа браузера к микрофону на внешнем сайте нужен HTTPS.

## Автотесты

```bash
python manage.py check
python manage.py test apps.tutor apps.education apps.assessments
```

Проверяются публикация и доступ по траектории, CSRF, ограничения сообщений и аудио, изоляция сессий, обработка сбоя AI, потоковая передача ответа и голосовые маршруты. Эти тесты используют подменённый транспорт; реальный AI следует отдельно проверить на двух лекциях с разными темами.
