# AI Edu backend

Backend виртуальной работы №1 `lecture_workshop@1.0.0`: [настройка AI API, локальный worker, API и схема документа](docs/workspace.md).

Письма регистрации и восстановления пароля: [настройка Resend, подтверждение email и API](docs/account-email.md).

Django REST API и инфраструктура платформы: PostgreSQL, Redis и MinIO. Frontend находится в отдельном репозитории и подключается к общей Docker-сети `aiedu-platform`.

## Запуск backend

1. Скопируйте `.env.example` в `.env` и замените значения `replace-with-...` случайными секретами.
2. Выполните из корня этого репозитория:

```bash
docker compose up --build -d
```

Compose поднимает PostgreSQL, Redis, MinIO и backend, запускает миграции и создаёт bucket. Backend API доступен в Docker-сети по `http://backend:8000` и локально на `http://localhost:8000`. MinIO Console доступна только локально на `http://localhost:9001`.

Создайте администратора платформы:

```bash
docker compose exec backend python manage.py create_platform_admin --email admin@example.com
```

Команда запросит пароль. Этот аккаунт получает роль `ADMIN`, но не системные права Django. Для системного superuser используйте отдельную команду Django `createsuperuser`.

Демо-данные можно добавить повторно без дубликатов:

```bash
docker compose exec backend python manage.py seed_demo
```

API использует `/api/v1/`. OpenAPI схема доступна по `/api/v1/schema/`, Swagger UI — `/api/v1/docs/`. Изображения хранятся в приватном MinIO bucket и выдаются через авторизованный endpoint backend.

## Быстрый запуск тестов

```bash
python -m pip install -r requirements.txt -r requirements-import-core.txt -r requirements-test.txt
python manage.py test --settings=config.settings_test --parallel 2 --noinput --durations 15 --timing
```

Этот же запуск используется в CI: полный набор тестов выполняется в двух процессах,
каждый со своей тестовой базой. PostgreSQL нужен для проверки блокировок worker;
миграции и тесты обновления схемы выполняются полностью. `config.settings_test`
использует быстрый хешер паролей только для тестов; рабочий `config.settings` не меняется.
`tblib` сохраняет traceback ошибок из параллельных процессов. В конце прогона выводятся
15 самых медленных тестов и время подготовки базы.

При повторных локальных запусках можно добавить `--keepdb`, чтобы переиспользовать
тестовые базы. Для последовательной отладки замените `--parallel 2` на `--parallel 1`.

## Переменные окружения

`.env.example` включает настройки Django, PostgreSQL, MinIO и лимит загрузки. Секреты хранятся только в локальном `.env`, который игнорируется Git. В production задайте `DEBUG=false`, сильный `SECRET_KEY`, `ALLOWED_HOSTS` и `CSRF_TRUSTED_ORIGINS` для своего HTTPS-домена.

## Production

Сначала запустите backend с production-конфигурацией:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up --build -d
```

Production backend использует Gunicorn и создаёт volume `aiedu-static` для Django static files. Затем в репозитории frontend запустите его production Compose. Внешний Nginx направляет API на backend и раздаёт Django static files из этого volume. TLS завершается на Nginx с передачей заголовка `X-Forwarded-Proto: https`.

Production-домен платформы — `https://aiedu.com.kz`. В серверном `.env` задайте:

```dotenv
DEBUG=false
ALLOWED_HOSTS=aiedu.com.kz,localhost,127.0.0.1,backend
CSRF_TRUSTED_ORIGINS=https://aiedu.com.kz
```

`ALLOWED_HOSTS` содержит имена хостов без протокола, `CSRF_TRUSTED_ORIGINS` — полные HTTPS origins. Backend читает существующий `.env` при создании контейнера; обновление исходников не заменяет этот файл. API браузера использует тот же домен и пути `/api/v1/`, поэтому отдельный CORS middleware не требуется. Cookie остаются привязанными к текущему хосту; после смены домена войдите заново.

В HTTPS server block внешнего Nginx укажите `server_name aiedu.com.kz` и сертификат этого домена. Маршруты должны сохранять исходный Host и протокол:

```nginx
location /api/ {
    client_max_body_size 32m;
    proxy_pass http://127.0.0.1:4000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_buffering off;
    proxy_read_timeout 180s;
}

location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

После изменения `.env` выполните в каталоге серверного backend следующие команды. Они сохраняют образ и тег текущего контейнера, в том числе если CI передавал тег только через окружение:

```bash
backend_image=$(docker inspect --format '{{.Config.Image}}' ai-edu-backend-1)
BACKEND_IMAGE="${backend_image%:*}" IMAGE_TAG="${backend_image##*:}" \
  docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  up -d --no-deps --no-build --force-recreate backend
```

Если меняли Nginx, примените конфигурацию через `sudo nginx -t && sudo systemctl reload nginx`.
Проверка: `curl -i https://aiedu.com.kz/api/v1/csrf/` должен вернуть `200`. Без сессии `/api/v1/auth/me/` возвращает `403`, после входа — `200`. Ответ `400` на оба GET обычно означает отклонённый Host; проверьте значения в контейнере:

```bash
docker exec ai-edu-backend-1 python -c "from config import settings; print(settings.ALLOWED_HOSTS); print(settings.CSRF_TRUSTED_ORIGINS)"
```

## Мягкое удаление

Пользователи, траектории, курсы, модули, учебные элементы, лекции, тесты, практики и медиафайлы имеют `deleted_at`. Обычный менеджер `objects` и связанные списки скрывают удалённые записи; для работы с архивом на сервере используется `all_objects`. Удаление экземпляра и `QuerySet.delete()` выполняют мягкое удаление в транзакции. Удаление траектории, курса или модуля также скрывает вложенные материалы. Блоки лекций, вложения, версии практик, вопросы, попытки, результаты, прогресс и права доступа остаются в базе; внешние ключи продолжают разрешаться для истории. Независимые тесты и практики, связанные с лекцией через старую модель, сохраняются при удалении только этой лекции.

`DELETE /api/v1/admin/users/{id}/` доступен администратору и дополнительно отключает аккаунт: вход и существующие сессии перестают работать. Собственный и системный аккаунты удалить нельзя. Удалённые материалы возвращают `404` в рабочих API и не учитываются в текущем прогрессе курса. Сохранённая история доступна через существующие отчёты. Email пользователей, адреса курсов и публичные ID остаются занятыми архивными записями; позиции элементов уникальны только среди неудалённых материалов. API восстановления пока не предусмотрен.

Перед запуском обновлённого приложения примените миграции: `python manage.py migrate`.

## Practice Engine

`LearningItem(PRACTICE)` задаёт положение в модуле и ссылается на `PracticeDefinition` и опубликованную `PracticeVersion`. Условия задания, конфигурация и критерии принадлежат версии. Сохранение редактора меняет только черновик; публикация создаёт следующую неизменяемую версию. Название и описание также фиксируются в версии. Начатая `PracticeSubmission` сохраняет свою версию при обновлении публикации. Новая попытка использует текущую публикацию.

В редакторе администратора кнопка «Изменить практику» открывает каталог `GET practice-types/`, из которого можно заменить выбранный тип для того же учебного элемента. Название и описание сохраняются, настройки заменяются начальными настройками выбранной практики. Смена типа создаёт отдельную `PracticeDefinition`, сохраняя прежнюю публикацию до явного обновления и не изменяя закреплённые версии попыток. Редактирование названия или описания само по себе не меняет тип и конфигурацию. Сейчас в каталоге доступна только `lecture_workshop@1.0.0`; новые зарегистрированные типы с frontend реализацией появятся в выборе автоматически.

`PracticeResult` хранит оценку отдельно от ответа: `self_assessment_score`, `automatic_score`, `teacher_score`, `effective_score`, `grading_source`, `psi_value`, `psi_source`. `lecture_workshop@1.0.0` и `guided_assignment@1.0.0` используют общие инструкцию и критерии, с источником `SELF_ASSESSMENT`. Сервер принимает состояния критериев и вычисляет Ψ = отмеченные / все критерии. Сдача требует подтверждения всех обязательных критериев; иначе возвращается ошибка, попытка остаётся открытой. После сдачи прогресс — 100%. Необязательные критерии тоже входят в Ψ. Автоматической оценки качества содержания нет. Исторические версии `checklist_practice` и мастерской без инструкции поддерживают прежний контракт.

API под `/api/v1/`:

| Метод и адрес | Назначение |
| --- | --- |
| `GET practice-types/` | Manifest, capabilities, схема, идентификаторы редактора/runtime |
| `GET items/{short_id}/practice/draft/` | Черновик, публикация и версии; только администратор |
| `PUT items/{short_id}/practice/draft/` | Сохранить `{practice_type, plugin_version, title, description, config}` |
| `POST items/{short_id}/practice/draft/` | Опубликовать сохранённый черновик |
| `GET items/{short_id}/practice/` | Условия закреплённой версии, своя попытка, результат и прогресс |
| `POST items/{short_id}/practice/start/` | Начать попытку или вернуть уже начатую |
| `POST items/{short_id}/practice/` | Сдать `{submission_id, submission_data: {checks: [true, false]}}` |
| `GET items/{short_id}/practice/history/` | Своя история с пагинацией |

Чужие попытки недоступны. Проверки Course Access, публикации и блокировок модулей применяются ко всем student endpoints. Повторная отправка одинакового ответа идемпотентна; изменение сданного ответа требует новой попытки. Снимок критериев и ответов сохраняется при сдаче. Повторное прохождение после неуспешного теста помечает прежнюю попытку неактуальной, сохраняя её историю и оценку. Формула Ω не изменена: она получает числовой Ψ из результата, а источник остаётся в базе. Практику или родительский материал можно мягко удалить при наличии попыток; версии и результаты студентов сохраняются.

Миграции переносят старые `LearningItem.practice_criteria` в версии и `PracticeCriterion`, существующие самооценки — в закреплённые submissions/results, сохраняя прежний прогресс и время активности. Несовпадающие старые критерии сохраняются отдельной исторической версией. Legacy `PracticeDefinition.kind/config` и снимки `PracticeSubmission.criteria/checks` сохранены для совместимости данных; новые типы используют version config и `submission_data/criteria_snapshot`. Ненастроенные старые практики требуют выбора типа в редакторе.

Перед запуском обновлённого приложения выполните `python manage.py migrate` (Docker Compose выполняет это автоматически). Откат к старой модели с одной сдачей на пользователя несовместим с несколькими новыми попытками; для такого отката восстановите резервную копию базы.

Добавление типа независимым разработчиком:

1. Реализовать контракт `PracticePlugin` в `apps/activities/registry.py`: manifest, `validate_config`, `materialize_config`, `evaluate`. Manifest содержит JSON schema. Валидатор обязан строго проверять ту же схему; `evaluate` рассчитывает оценку на сервере и возвращает `Evaluation` с источником, признаком завершения и снимком. Зарегистрировать конкретную версию через `registry.register(plugin)`.
2. На frontend реализовать `PracticePlugin` из `src/practice/types.ts`: `ConfigEditor`, `StudentRuntime`, `initialConfig`, `validateConfig`, и вызвать `registerPractice` в `src/practice/registry.ts`. Версия плагина должна совпадать с backend manifest. Каталог показывает только зарегистрированные backend типы; карточка отключена, если frontend реализации нет.
3. При несовместимом изменении схемы зарегистрировать новую версию плагина, оставив старую доступной для закреплённых попыток. Добавить проверки схемы, серверного оценивания, доступа и сохранения версии. Изменений Curriculum и формулы Ω для регистрации типа не требуется.

Проверки ядра: `python manage.py test apps.activities apps.education.test_adaptive`.

## Импорт лекции из файла

В редакторе лекции нажмите **«Импорт из файла»**: PDF, DOCX или PPTX до 10 МБ. После обработки отображается только будущая лекция. Кнопками **«Добавить в конец»** или **«Заменить содержимое»** обязательно выберите способ переноса — изначально ни один не выбран — и нажмите **«Перенести в черновик»**. Название, описание и вложения не меняются. Перенос отменяется одним действием «Отменить». Для учеников изменения становятся доступны только после явной публикации.

Backend сохраняет приватный `LectureImportJob`, возвращает `202` и не запускает OCR в HTTP-процессе. Отдельный worker берёт задания из БД с блокировкой и lease, запускает обработку в дочернем процессе с общим таймаутом, сохраняет изображения как обычные `MediaFile` и результат как блоки существующего редактора. После аварийного завершения worker задание повторяется один раз. Повторный импорт доступен загрузкой файла заново. Закрытие окна не прерывает обработку; последние пять импортов доступны при следующем открытии.

Распознавание выполняется автоматически, без пользовательских переключателей. DOCX обрабатывается `python-docx`, PPTX — `python-pptx`: сохраняются родные заголовки, цитаты, выделение, списки и таблицы. Для слайдов используется порядок сверху вниз и слева направо, сохраняются номер слайда и координаты. PDF сначала проходит нативное извлечение текста и layout через Docling без OCR. Предварительная проверка PDFium выбирает страницы с изображениями, отсутствующим или повреждённым текстовым слоем. Только они проходят второй этап с Tesseract (`rus+eng+kaz`): смешанные страницы — распознавание областей, сканы и повреждённый слой — OCR всей страницы. Результаты объединяются в исходном порядке страниц; цифровые страницы повторно через OCR не обрабатываются. Если нативная конвертация завершилась ошибкой, используется OCR как резервный путь. Картинки в Office также проходят OCR; извлечённый текст добавляется рядом с изображением.

LangChain включается только при признаках неоднозначной структуры: текст после OCR, нераспознанные заголовки, короткие выделенные строки, признаки списка, цитаты или кода, либо отсутствие заголовков среди коротких абзацев. Явные заголовки, цитаты, списки и таблицы из источника остаются без вызова модели. Если настроены `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, неоднозначные абзацы классифицируются пакетами: заголовок / цитата / код / список / текст. Ответ валидируется Pydantic; идентификаторы и порядок должны точно совпадать с источником. Модель не возвращает и не переписывает текст, не получает инструментов или доступа к редактору. Ошибка модели оставляет исходные фрагменты и предупреждение. Без AI-конфигурации импорт работает по структуре файла; при неоднозначности предлагается проверить результат вручную.

Запуск Docker (база, MinIO и backend должны быть настроены как обычно):

```bash
docker compose up -d --build backend import-worker
docker compose logs -f import-worker
```

В образе worker установлены CPU PyTorch, Docling и Tesseract с тремя языками. Первое распознавание PDF скачивает модели Docling; они кешируются в томе `import_models`. Нужен исходящий доступ к хранилищу моделей Hugging Face. Worker ограничен 2 CPU / 4 ГБ; при больших документах увеличьте ресурсы или разбейте файл. По умолчанию PDF/PPTX ограничены 100 страницами/слайдами, документ — 5000 элементами и 500000 символами, готовая лекция — существующими лимитами 100 блоков и 50000 символов на блок. Превышение лимитов даёт ошибку без усечения текста. Общий таймаут — 900 секунд; настройки находятся в `.env.example`. В Nginx требуется `client_max_body_size 32m` (пример выше).

Локальный запуск без Docker:

```bash
python -m pip install -r requirements-import.txt
# Установите системный Tesseract и языки rus, eng, kaz; проверьте tesseract --list-langs.
python manage.py migrate
python manage.py run_lecture_import_worker
```

Примените миграции перед запуском обновлённого frontend. Ответ `GET/PUT lessons/{id}/draft/` содержит `revision`; новый редактор передаёт её при сохранении и публикации. Несовпадение возвращает `409 draft_conflict` без перезаписи сохранённой версии. Старые клиенты без `revision` поддерживаются для совместимости.

API (все endpoints только для администратора):

Импорт сохраняет цвет текста и выделение фрагментов DOCX/PPTX, включая цвета темы и текст ячеек. Нумерация Word читается из OOXML, PowerPoint — из настроек абзацев и шаблона; сохраняются вложенность, начало и перезапуск списков. Для PDF цвета символов и аннотации выделения извлекаются из нативного слоя только при точном совпадении текста и области. Для текста, полученного исключительно через OCR, цвета не восстанавливаются.

| Метод | Адрес | Действие |
| --- | --- | --- |
| GET | `lessons/{id}/imports/` | Пять последних заданий и доступность AI |
| POST multipart | `lessons/{id}/imports/` | `file`; этапы распознавания выбираются автоматически |
| GET | `lessons/{id}/imports/{uuid}/` | Состояние, этап, ошибка, результат и исходные элементы |
| GET | `lessons/{id}/imports/{uuid}/source/` | Приватный оригинал |

Для инструкции практики тот же механизм доступен по `items/{id}/practice/imports/`,
`items/{id}/practice/imports/{uuid}/` и `items/{id}/practice/imports/{uuid}/source/`.
Используются существующий import-worker, форматы PDF/DOCX/PPTX и лимит 10 МБ.
Перед запуском обновлённого frontend примените миграцию `lessons.0004_practice_instruction_imports`
и обновите backend и import-worker. Распознавание само по себе не меняет практику:
администратор проверяет результат, выбирает добавление или замену инструкции и сохраняет
черновик обычной кнопкой. Критерии и исходные вложения сохраняются. Изображения в инструкции
доступны студентам после публикации с теми же проверками доступа, что и файлы практики.

Ограничения: произвольная вёрстка переводится в поток документа; диаграммы PowerPoint и некоторые векторные изображения требуют ручного добавления, формулы Word переносятся текстом. Сложные формулы PDF, многоуровневые списки, объединения ячеек и порядок элементов в сложных колонках необходимо проверить по исходнику. Отсутствие подходящего форматирования в источнике не позволяет гарантированно распознать цитату или код без AI. Интерфейс сообщает об этих случаях. DOC/PPT нужно сначала сохранить как DOCX/PPTX. Оригиналы и результаты остаются приватными, изображения привязаны к заданиям и защищены от `cleanup_unused_media`; автоматическое удаление истории пока не выполняется.

Проверки:

```bash
python -m pip install -r requirements-import-core.txt
python manage.py test apps.lessons apps.mediafiles apps.education
# Цвета и списки на настоящих DOCX/PPTX и нативном PDF (без OCR):
python manage.py test apps.lessons.test_import_formatting
# Linux-образ с настоящими OCR/Docling, отдельная проверка в CI:
docker compose run --rm -e RUN_LECTURE_OCR_TESTS=1 import-worker python manage.py test apps.lessons.test_import_ocr --noinput
```

CI собирает и публикует отдельный образ `*-import-worker`, проверяет распознавание обычного PDF, сканированного PDF и картинки в DOCX, затем обновляет worker вместе с backend. Ключи модели остаются только на backend.
